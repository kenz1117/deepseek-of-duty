## 2. 公平性审查

### 2.1 🔴 CRITICAL — 刷兵全链路无最小距离约束

这是最严重的公平性缺陷，且是**多层叠加**造成的：

**第一层：距离门控作用在"区域质心"而非"实际刷兵点"**
`src/systems/spawn.js:138-139` 对区域质心做 10.8–88m 的硬门控：
```js
const d = Math.hypot(zone.centroid.x - playerPos.x, zone.centroid.z - playerPos.z);
if (d < BAND_MIN * 0.6 || d > BAND_MAX * 1.6) continue;  // 10.8 .. 88 m
```
但随后 `src/systems/spawn.js:166` 在该区域内**任意取点，零距离过滤**：
```js
const point = sel.zone.points[Math.floor(rng() * sel.zone.points.length) % ...];
```
区域跨越 50–120m 时，实际刷兵点可以是 130m 外。

**第二层：可达性检查不检查距离**
`src/main.js:2526-2529`：
```js
function spawnReachesPlayer(sp) {
  if (sp.y > 1) return true;                    // 屋顶刷兵点：直接放行，无任何检查
  return !!nav.findPath(sp.x, sp.z, 0, controller.pos.x, controller.pos.z, controller.pos.y);
}
```
地面点只验证"存在一条路径"，不验证路径长度。屋顶点（81 个刷兵点中有 22 个是屋顶点）**完全绕过检查**。

**第三层：点位抖动范围太小，无法挽救远距离点**
`src/main.js:3561-3568` 的 `placePlanPick` 最多试 5 个位置，抖动半径上限约 3.5m，对 130m 的点位无济于事。

**实测证据**【实测】：wave 8，玩家位于自然出生点 `(1.2, 33)`，第 15 秒时敌人实际距离为 **60 / 68 / 69 / 71 / 73 m**；更早一轮采样中首批敌人的距离为 **137 m**。而 `src/main.js:2587` 的传统选择器明确写着期望交战带 18–45m：
```js
if (d >= 18 && d <= 45 && d > midD) { midD = d; mid = sp; }
```
**新方案路径把这个下限弄丢了** —— 旧代码有 `if (d > 10 && d < nearD)` 兜底，新路径没有。

### 2.2 🟡 NEEDS WORK — 无出生预警

`src/main.js:3889` 让敌人**正对玩家**生成：
```js
const yaw = Math.atan2(-(playerPos.x - sp.x), -(playerPos.z - sp.z));
```
`Enemy.spawn()`（`src/entities/enemy.js:639-706`）不设置任何延迟、标记或音效；`awareness` 从 0 起步。玩家实际获得的只有 1–3 秒的反应时间（感知增益 0.70–1.30/s + 难度档反应延迟 0.32–1.55s，`src/systems/ai/tuning.js:20-23`）。**勉强够反应，但谈不上"预警"**。

### 2.3 🔴 CRITICAL — 毒圈 DPS 阶梯是死代码

`src/systems/zone.js:35` 定义了完整的伤害阶梯：
```js
const DEFAULT_DPS = [1.0, 2.0, 3.5, 5.5, 8.0, 11.0, 14.0, 18.0];
```
并导出到快照（`zone.js:318`）。但 `src/main.js:2350-2356` **从未读取它**：
```js
G.zoneDmgT += dt;
if (G.zoneDmgT >= 1) { G.zoneDmgT -= 1; applyZoneDamage((G.maxHp || 100) * 0.10); }
```
→ **每个阶段都是恒定 10 HP/s**，即阶段 0 是设计值的 10 倍。`docs/PROPOSAL-VERSUS-ZONE-MILESTONE.md` 承诺"分阶段递增（1.5 → 10 HP/s）"，实现记录声称"1→14 HP/s 阶梯递增" —— **两者都与代码不符**。100 HP 玩家在圈外 10 秒即死，且圈伤绕过护甲（`src/main.js:2250` 只扣 `G.hp`）并阻断回血（`G.sinceDamage = 99`）。

**附带问题：圆环锚定到整张地图而非站点**
`src/systems/zone.js:12-19` 的注释明确警告过这个坑（"以地图中心画圆会在四个站点中的三个切断可玩区域"），但 `src/main.js:2230-2232` 在 versus 模式传入的是 `level.bounds`：
```js
const rect = G.versusMode && level && level.bounds ? { ...level.bounds } : ...
```
`level.bounds` = 425.2 × 370.4m（`src/world/level.js:6514`）→ 起始半径 290.4m，终局 25.9m，且每阶段质心最多漂移 85m（`zone.js:151-163`）。**终局 26m 的决赛圈完全可能落在站点之间的空地**，玩家需要跑 150m+（冲刺 7.0 m/s ≈ 21 秒）同时承受 10 HP/s。

**小地图看不到圈**：`src/ui/minimap.js:11` 的 `RANGES = [42, 70]`。在 range 70 下缩放比为 1.071 px/m，290m 的圈是 311px —— 远超 150px 画布，圈外压暗（`minimap.js:229-236`）会淹没整张小地图，**直到最终阶段 r≈26m 玩家才看得见圈边界**，且没有屏幕外指示器。

### 2.4 🟡 NEEDS WORK — 死亡循环与死亡螺旋

- **单人多波 PvE**：一次死亡即结束整局（`src/main.js:5292-5313` → `finishRun()`），无生命数、无续关；节拍制任务可"从节拍 N 重试"（`src/main.js:5307-5310`）。
- **LAN 合作**：倒地 / 30 秒流血 / 3.5m 内 2.0 秒扶起 / 50% 血量 / 全队覆灭 5 秒重部署（`src/systems/medical.js:17-21`）—— **这部分设计得很好**。
- **隐藏的死亡螺旋**：护甲在清波时**不恢复**（`src/main.js:3959-3966` 只补弹药和手雷），只能靠升级卡（`src/main.js:563`）和拾取（`src/main.js:4915`）拿回。等效血量从 180（100 血 + 60 甲）降到 100，**后半程比前半程严苛 1.8 倍，HUD 毫无提示**。
- 结算面板（`src/ui/results.js:304-306`）只有击杀数/波次/分数，**没有死亡数**。

### 2.5 ✅ GOOD — versus 模式平衡（前提需更正）

`docs/versus-1v7-fairness-report.html` 是一份**事后复盘**：1v7 是 commit `6fb9d01` 引入的特例，已被回退为 4v4 补位。代码与之一致：
```js
// src/main.js:1726-1729
// A solo host therefore gets 3 allies + 4 enemies, never a 1v7 deathmatch.
const fill = Math.max(0, VERSUS_TEAM_SIZE - counts[team]);   // VERSUS_TEAM_SIZE = 4
```
实际存在的补偿机制：bot 用 D3 而非 D4（`src/main.js:1739`）、HP 80（`:1741`）、`damageMult 1.15`（`:1741`）、2 秒出生无敌（`:1742`）、落后方 ±30% 命中率橡皮筋（`src/systems/conquest.js:241-247`）、20 秒不开火部署窗口（`src/main.js:1414`）。**这部分是全项目公平性做得最好的模块。**

**唯一的漏洞**：bot 复活使用固定槽位锚点（`src/main.js:2419-2425`），既没有人类玩家享有的敌情感知复活点，也**没有出生无敌**，而且**正对玩家出生**。熟悉地图的玩家可以蹲点刷 bot。

### 2.6 🔴 CRITICAL — LAN 伤害事件完全客户端信任

中继服务器会给事件打上发送者 id（`server/lan.mjs:308-313`）并只转发给 host（`:317-321`）。但 host 的 `'pdmg'` 处理（`src/main.js:5838-5846`）**完全信任载荷**：
```js
versusApplyPlayerDamage(msg.target, msg.msg.amount || 0, msg.team, !!msg.headshot);
```
`target`、`amount`、`killerTeam` **三项全部由客户端提供且未经验证**。`versusApplyPlayerDamage` → `onVersusDeath` → `G.teamScores[killerTeam] += 1`（`src/main.js:2459-2472`, `:2165-2171`）。

**一个客户端即可**：瞬间击杀任意玩家（含队友）、**把击杀分记到任意阵营名下**。`makeFire` 虽把伤害钳制在 `[0.5, 3]`（`src/net/lanProtocol.js:239`），但 `'pdmg'` 路径完全绕过 `makeFire`。

文档已披露"人打人的命中判定在客户端（LAN 信任模型）"，但**没有披露其严重性是"任意击杀 + 刷分"，而不只是命中判定优势**。

其余网络层是健康的：毒圈 host 权威 + 客户端只读镜像（`zone.js:322-341`）、里程碑链 host 权威（`milestones.js:207-210`）、征服模式 host 权威（`conquest.js:201-221`）、消息限速 240 msg/s、单包上限 16 KB。

### 2.7 🟡 NEEDS WORK — 可访问性

`src/core/settings.js:10-23` 提供：灵敏度、ADS 灵敏度、FOV、反转 Y 轴、音量、减弱动效、画质、帧率上限、运行模式、路标、主武器、语音。

**缺失**：瞄准辅助、敌人命中/伤害强度调节、难度选择、色盲模式、按键重绑定。

难度**不可由玩家选择**：`diffForWave(n)`（`src/main.js:475-479`）按波次自动匹配，玩家**无法用低难度重玩已通关的战役**。`src/ui/controls.js:43-89` 是静态按键表，不是重绑定系统。

## 3. 可玩性审查

### 3.1 🔴 CRITICAL — 波次 AI 死锁（wave 8 / D4 及以上）

**这是本次审查最重要的发现，且可稳定复现。**

**实测数据**【实测】（`tools/ai-probe.mjs`，玩家在自然出生点 `(1.2,33)`，AUTO=1 玩家持续开火）：

| 波次 | 难度 | AI profile | engage 采样 | LOS 命中 | 玩家受伤 | 击杀 |
|---|---|---|---|---|---|---|
| 1 | D1 | garrison | 0 | **0 / 0 次检查** | 0 | 0 |
| 5 | D3 | hunter | **259** | **194 / 294** | **15.9** | **4** |
| 8 | D4 | hunter | **7** | 7 / 183 | **0** | 1 |
| 12 | D5 | hunter | **0** | **0 / 0 次检查** | **0** | 0 |

wave 5 完全正常，wave 8 和 12 完全失效。

**45 秒长时采样的距离轨迹**（wave 8，取每个采样点的最近敌人距离）：
```
t= 1.9 → 59.6m   ┐
t=20.3 → 59.6m   │ 平台期 20 秒，距离几乎不动
t=21.3 → 57.7m   │
t=26.8 → 34.9m   ┘ 终于逼近
t=30.4 → 26.8m   ← 首次进入交战范围
t=31.4 → 54.3m   ← 跳回 54m！（玩家此时击杀了 1 个敌人）
t=41.4 → 59.6m   ┐
t=45.1 → 59.6m   ┘ 再次卡死
```
45 秒内玩家受到 **0 点伤害**，敌人 183 次 LOS 检查仅命中 7 次。

**根因链（五个因素叠加）**：

1. **刷兵距离失控**（§2.1）—— 敌人实际生成在 60–137m 外，而 rifleman 的交战范围只有 48m（`src/entities/enemy.js:48-49`）。

2. **`hunter` profile 没有巡逻 → 未警觉敌人变雕像**
   `src/systems/ai/profiles.js:40`：
   ```js
   hunter: { id: 'hunter', intel: 'area', patrol: null, zoneAnchor: false, standoffMod: 0 },
   ```
   `src/entities/enemy.js:1064-1068` 的未警觉分支：
   ```js
   } else if (this.profile && this.profile.patrol) {
     this.state = 'patrol';
   } else {
     this.state = 'idle';        // ← hunter 走这里：speedTarget = 0，永久站桩
   }
   ```
   实测中 **45% 的敌人采样处于 `idle` 状态**。

3. **屋顶刷兵点制造永久雕像**
   `src/main.js:493-513` 的 `chooseArchetype` 注释写明"roof snipers from 6"，wave 9+ 有 14% 概率刷 sniper。实测捕捉到一个 sniper 位于 `(-54, 10) y=3.8`，**从第 2 秒到第 15 秒 `sp=0.00` 纹丝不动**，且紧邻另一个同坐标的 rifleman（两个敌人完全重叠）。

4. **flank 路点由"区域质心"而非玩家派生 → 永久横向绕圈**
   `src/systems/ai/director.js:168-176`：
   ```js
   const threat = e.lastSeen || stimulusFor(e) || areaAnchor(playerPos);
   const fp = pickFlankPoint({ from: e.root.position, threat, side: e.aiSide, ... });
   ```
   `areaAnchor`（`director.js:412-419`）返回的是**玩家所在区域的质心**，不是玩家位置。而 `src/entities/enemy.js:1094` 的侧翼终止条件是：
   ```js
   if (fd <= 2.6 || dist < 12) this.flankDone = true;
   ```
   敌人在 55m 外，`dist < 12` 永远不成立 → 侧翼永不结束 → 导演每 5–9 秒重掷一个新路点（`director.js:163`）→ **士兵永远在侧翼横向绕圈，永远不接近玩家**。

5. **感知/交战范围刚好卡在盘旋半径之外**
   `src/systems/ai/perception.js:137`：
   ```js
   const range = Math.min(B.sight * AM.sight, (e.def.engageRange || 70) * 1.15);
   ```
   D4 的 `sight = 82`，rifleman 的 `engageRange = 48` → 感知上限 **55.2m**，交战上限 **48m**。而敌人盘旋半径是 **54–59m** —— **正好在射程外侧**。

6. **波次不补充**：实测 `alivePeak` 稳定在 6（`aliveCap = Math.min(12, 6 + 2*(coopAllyCount()-1))`，`src/main.js:3917`）。玩家击杀 1 个后剩余 5 个仍在 54m 外，队列已空 → **波次永久僵持**。

**次生问题**：即使敌人偶尔获得 LOS（183 次中 7 次），玩家仍然受到 0 伤害。原因是反应延迟（D4 为 0.46–0.86s）+ `aimSettle` 爬升（0.74s），而 LOS 保持时间不足。

**修复建议（按性价比排序）**：
| 优先级 | 修改 | 位置 |
|---|---|---|
| P0 | 刷兵点增加硬性最小距离（≥22m），作用于**点位**而非质心 | `src/systems/spawn.js:163-168`、`src/main.js:3561-3568` |
| P0 | `spawnReachesPlayer` 增加距离上限，屋顶点不再无条件放行 | `src/main.js:2526-2529` |
| P0 | `investigate` 目标优先于 `playerPos` 的逻辑改为"仅在玩家位置不可知时兜底"，并给区域情报加**随时间收敛**的误差 | `src/entities/enemy.js:1262-1265`、`src/systems/ai/profiles.js:147-151` |
| P1 | `hunter` profile 增加 `patrol`（或把未警觉的 `idle` 改为沿区域质心游走），消除雕像 | `src/systems/ai/profiles.js:40`、`src/entities/enemy.js:1064-1068` |
| P1 | 侧翼路点在玩家**不可见**时应由最后已知位置或玩家真实位置的粗略估计派生，而不是区域质心；`flankDone` 增加超时兜底 | `src/systems/ai/director.js:168-176`、`src/entities/enemy.js:1090-1096` |
| P1 | 波次补充机制：存活数低于目标时按间隔补员，避免一次击杀导致波次缩水 | `src/main.js:3912-3923` |
| P2 | 为敌人加"距离过远时强制接近"的兜底状态（如 `closeout`），超出 engageRange × 2 时无视角色直接压上 | `src/entities/enemy.js:1219-1284` |

### 3.2 ✅ GOOD — 节奏与多轴到达设计

`src/systems/spawn.js:129-170` 的生存模式生成器是**真正的亮点**：一轴取正面（`off ≤ 90°`）、一轴取侧后（`off > 90°`），并带 2 波轮换记忆（`ROTATION_MEMORY = 2`）防止重复刷同一区域。防守模式强制进攻轴间隔 ≥55°（`spawn.js:202`），撤离模式会在玩家背后安排追兵（`spawn.js:244-248`）。

**问题不在设计，而在 §2.1 的距离门控把这份设计的落点搞砸了。**

### 3.3 🟡 NEEDS WORK — 玩法循环的缺失反馈

- 波次推进没有"敌人正在接近"的压迫感反馈（因为敌人根本没接近）。
- 没有超时机制：波次可以无限期僵持，玩家只能靠主动推进或退出。
- `engagedWithLosPct` 这类 AI 健康度指标**只存在于探针脚本里**，没有暴露到游戏内调试面板。

## 4. 剧情合理性审查

### 4.1 剧情梗概

### 4.3 分项评价

**叙事—机制融合：基本成立，三处软肋**
节拍链确实驱动玩法（`main.js:3504-3508`、`1163-1174`、`3580-3634`），Boss 相位改变机制（`story.js:123-128,221-226,347-352`），情报/档案是真实可收集物。但：
- OP05 的 `interact` 节拍"搜出情报"（`story.js:117`）**不给予任何奖励** —— `mountBeatInteract`（`main.js:1236-1249`）只完成目标。
- OP02 的 `infil` 节拍"别惊动守军"**没有警觉机制**，只有一个 2.5 秒的区域计时（`beats.js:68-70`）。
- **故事从不回应失败**：死亡只有通用的"OPERATOR KIA · 任务失败"（`index.html:698`），无角色反应，且 `finishOperation()`（`main.js:4402-4409`）**只标记成功，从无失败态**。唯一的死亡反应台词（"全队倒了……重新集结"，`main.js:6770`）偏偏在**完全没有剧情的 LAN 合作模式**里触发。战役是严格单调递增的。

**角色声音：偏弱**
所有敌人都共用同一套中文台词（`barks.js:18-29`），字幕永远配音频（`barks.js:125`，`public/audio/voice/enemy/` 有 12 个 MP3）。功能上没问题，但**没有按角色/阵营区分**：哈桑、替身、卡里姆、萨利姆在战斗中叫声完全一样（触发点在 `director.js:181-250`、`perception.js:295`，从不针对 Boss）。

**铺陈与节奏：可接受，有一处无障碍缺口**
实测全流程文本约 **1,960 个中文字**（无线电 872 / 简报 ≈280 / 复盘 284 / 节拍 HUD 153 / 过场 371），约合 5 分钟阅读量，分散在 90–140 分钟战役中，通过非阻塞 HUD 队列投放（`hud.js:454-476`，每条 7.2 秒，`main.js:3600`）—— **不影响节奏**。过场可跳过（`cinema.js:396`）。
**缺口**：24 条过场台词中有 11 条是 `silent: true`（`cinema.js:97-99,117-118,137-138,157-158,175-177`）→ **第二幕过场完全无音频**（无 MP3，TTS 被 `cinema.js:342` 抑制），且没有字幕开关选项。其余全部字幕优先（对聋人友好），这 5 段第二幕场景是纯文本损失。

**模式一致性：接缝处是断的**
战役是单人专属，LAN 合作明确"无战役合作"（`docs/MULTIPLAYER-DESIGN.md:63`），走 `G.operation = null` 的通用里程碑链（`main.js:6503`）。**但 VEGA 仍在非剧情模式里说话**：毒圈预警"毒圈将在 15 秒后开始收缩"（`main.js:2336`）、追击播报（`main.js:2657`）、合作模式的"阶段完成。推进到下一个目标。"（`main.js:1344`）—— 战役指挥官在指挥 4 人 LAN 小队和一场缩圈对战，缺任何世界观桥接。另外 `docs/MULTIPLAYER-DESIGN.md:37` 仍写着 versus "**Not shipping**"，而代码已经发布了。

**Moth 与炮击：都是有剧情载体的，不算突兀**
`src/entities/moth.js` **不是生物**，而是 MOTH 本人（毛线帽、耳机、平板、"UAV // ISR"臂章，`moth.js:9,23`），只在 OP10 撤离点实体生成（`main.js:3298,3267`），并在 OP09/10/12/14 通过无线电出现 —— 完全叙事内。炮击同样如此：既是玩家 11 杀连杀奖励（`guide:106`），也是萨利姆在 60% HP 时的场外火力支援（`story.js:348`、`main.js:4346-4349`）—— **同一系统被敌方武器化，是全项目最干净的机制—叙事融合**。唯一缺口：**玩家的空袭没有叙事来源**，VEGA 从不播报。

## 5. 敌人 AI 算法审查

### 5.1 ✅ 架构层面：分层设计是全项目最优秀的部分

```
Perception（感知）  →  Awareness（0..1 置信度）
                          →  Reaction（分层反应延迟）
                          →  Hearing（枪声/弹着/队友阵亡，带声学遮挡）
                          →  Suppression（压制）
Director（导演）     →  0.3s 节奏派发角色（assault / flank / suppress / hold）
                          →  掩体预约（保证两人不抢同一掩体）
                          →  真实侧翼路点（A* 绕行）
                          →  分层情报（陈旧位置提示，而非开挂实时坐标）
Enemy（个体）       →  状态机 + 转向 + A* + 分离 + 掩体 peek/hide + 士气
```

几个值得肯定的细节：
- **"公平视野"**：士兵只知道自己能感知到的位置，导演喂的是**区域质心 ± 12–20m 误差**（`director.js:199-233`），而不是实时坐标 —— 这条设计直接消灭了"开挂感"。
- **子弹终点权威**：每次开火都重算枪口到目标的实际路径（`enemy.js:1948-1953`），被墙挡住就强制 miss 并把曳光截断在墙面上。配合 `losCache` 的 0.13–0.36s 陈旧度，解决了经典的"隔角穿墙"。
- **绕角后的复核**：玩家在 0.15s 内断开视线时，已命中的骰子会再过一次几何校验（`enemy.js:1954-1960`）。
- **士气系统**：队友阵亡影响小队命中与角色倾向（`director.js:82-91`），受伤的步枪手会进入 panic、瞄准抖动、精度上限下降（`enemy.js:839-845`、`enemy.js:995-1005`）。

### 5.2 🔴 收敛算法有结构性缺陷

见 §3.1。核心问题是**三个"目标优先级"规则在长距离上互相冲突**：

```js
// src/entities/enemy.js:1262-1265  (advance 状态)
const tgt = this.investigate
  || (this.lastSeen && this.lastSeenT < 6 ? this.lastSeen : null)
  || (this.profile && this.profile.zoneAnchor && this.zoneAnchor)
  || playerPos;
```
- `investigate` **一旦设置就永久压过 `playerPos`**，只有真正看到玩家才会被清除（`perception.js:273`）；
- 而 `investigate` 来自区域质心 ± 误差，**误差不随时间收敛**；
- 同时 flank 分支（`enemy.js:1223-1229`）又**优先级更高**，走的是另一个由区域质心派生的路点。

结果是：**三个以"区域质心"为锚的目标系统叠加，把士兵牢牢钉在玩家周围的区域中心附近横向游走。**

**建议的架构级修复**：把目标来源分层并明确优先级——
1. `playerPos`（仅当 `awareness > 0.7` 或无任何其他情报时使用，且应带随距离衰减的误差）
2. `lastSeen`（最后目击点，带时间衰减）
3. `investigate`（刺激源）
4. `areaAnchor`（**仅作为"向玩家方向移动"的朝向提示，不得作为终点**）

即：**区域情报应当用来确定"往哪个方向找"，而不是"到哪里去"。**

### 5.3 🟡 游荡覆盖率不足

`hunter` 与 `squad` profile 的 `patrol: null`（`profiles.js:40,45`）。实测 wave 8/12 中 **45% 的敌人采样处于 `idle` 状态**（`enemy.js:1068`）。唯一的巡逻 profile 是 `garrison`（`profiles.js:44`），仅用于战役 wave 1（`main.js:3508`）。

**任何非战役驱动的波次，敌人未警觉时都是雕像。** 这在"隐藏自己"的玩法里反而是优点（偷袭可行），但在实际体感到"敌人卡住了"。

### 5.4 🟡 掩体系统开销

`src/systems/ai/cover.js:69-88` 的 `nearbyFaces` 在每次掩体搜索中为**每个碰撞体**分配一个数组 + 一个 4 元素数组 —— 单次调用约 300 个数组，实测每帧最多触发约 9 次。

### 5.5 ✅ 公平性反作弊做得扎实

- 出生即面向玩家（`main.js:3889`）——对敌人公平。
- 士兵不会用实时坐标追踪（§5.1）。
- `maxFiring` 全局开火预算（`src/main.js:484-491`）限制同时开火人数，是 swarm 死亡可读性的关键刹车。
- 友好伤害在敌人侧减 35%（`enemy.js:770`）、人类侧减半（`main.js:4772-4774`），且友伤**不会**触发警觉/找掩体/恐慌（`enemy.js:762-779` 有明确注释说明为什么）。

## 6. 整体性能审查

### 6.1 🟡 每帧临时对象：5000–7000 个/帧

**主因**是 `src/systems/navgrid.js:32-35` 的 `cellOf` 每次调用都返回**新对象**：
```js
const cellOf = (x, z) => ({ c: ..., r: ... });
```
它被 `lineWalkableLayer`（`navgrid.js:206`）在 **每 0.35m 采样一次**（`navgrid.js:203`）调用。

每帧调用方：
- `src/systems/ai/perception.js:197` —— 每个（敌人 × 在范围内的噪音）组合，**每帧每敌人都算**。噪音列表上限 24 条（`perception.js:57`），玩家开火产生半径 42m 的噪音（`main.js:4211`）、敌人每次开火产生半径 22m 的噪音（`main.js:5399`）。一个 22m 半径噪音 = 63 次 `cellOf` 分配。
- `src/main.js:7111` —— 卡死保护，每敌每帧一次，全程玩家距离（40–60m → 115–172 步）。

**估算**：14 敌人 × 约 24 噪音（半径过滤后约 4–8 个命中）→ 约 80–144 次 `lineWalkable`/帧 × 约 60–120 步 = **每帧约 5000–7000 个 `{c,r}` 对象（30–42 万/秒）**。这是一个约 10 行的改动就能消除 85% 的分配。

次要来源：`enemy.js:2096`（`followPath` 每帧每敌人返回新 `{x,z}`）、`main.js:1943-1955`（versus 模式每敌每帧新建对象）、`main.js:3916,3924,3976`（`updateWaves` 每帧 3 次 `enemies.filter`）、`enemy.js:199,207`（每次 LOS 检查分配 `{blocked,tEnd}`）。

### 6.2 ✅ 光线追踪 / BVH：优秀

**AI 视线完全不依赖光线追踪** —— `src/entities/enemy.js:885-919` 用解析式 AABB slab 测试（`segmentBlockedByColliders`，`enemy.js:152-206`），并正确处理高度/顶面剔除。感知层有双重节流：视觉锥 + 距离预筛（`perception.js:139-160`）+ LOS 计时器 0.13–0.23s（`perception.js:164-165`）。

`three-mesh-bvh` **确实在用**：`src/core/bvh.js:15-17` 给 `Mesh.prototype.raycast` 打补丁，`src/world/level.js:6335` 为合并后的世界缓冲（~120 万三角形）构建 BVH。

**稳态每帧光线追踪次数 ≈ 0**（玩家开火时按弹丸数 1–9 次；标签遮挡 6 条/0.22s；太阳遮挡 1 条/0.18s）。

小瑕疵：`main.js:4116` 每次开火都 `level.bulletTargets.slice()` 再 push 14 个 hitbox —— 每发一次的无谓数组拷贝。

### 6.3 🟡 AI 无调度：每个敌人每帧全量更新

`src/main.js:7046-7099` 对每个可见敌人每帧调用完整的 `e.update(dt, enemyCtx)`，包含感知、掩体请求、转向、A*、分离、动画、开火。**150m 外墙后的士兵也在每帧跑 A\* 和感知。**

只有**视觉** LOD：26m 外关闭阴影投射（`main.js:7125-7132`）、24m 外隐藏细节网格（`main.js:7133`）。

### 6.4 🟡 每次刷兵重建约 55 个几何体

`src/main.js:3892` 每次刷兵都调用 `e.setArchetype(type)` → `rebuildVisual()`（`enemy.js:407`）→ 销毁并重建整个 rig（`soldierParts.js:56-87` 的 `box()`/`rbox()`/`torus()`/`cyl()`/`sph()` 全部 `new THREE.*Geometry`），再 `buildHitboxes`（`enemy.js:559-594`）分配 **14 个全新 BoxGeometry**。

按刷兵间隔 0.75–1.35s（`main.js:3921`），波次中约 **40 次/秒的几何体重建 + GPU buffer 上传**。

材质方面是好的：约 33 个共享材质一次构建，士兵材质按 variant 缓存（`soldierParts.js:283-320`），武器材质为全局单例。

| `addPoint` 辅助函数 | 11 | `level.js:2770`（调用点 2780×3, 2787, 2789, 2790, 2791, 2802, 3263, 3289） |
| 显式 `new THREE.PointLight` | 11 | `level.js:871, 1288, 1389×2, 1438, 1683, 3751, 3839, 4099, 4995, 5240` |
| `addFire` 火焰灯 | 7 | `level.js:5236-5246`（调用点 4689, 6153, 5 个燃烧桶） |
| FX 枪口 / 爆炸灯 | 2 | `fx.js:180, 185` |
| MOTH 盟友 | 2 | `moth.js:52, 56` |

**约 34 个点光源全部在同一个前向渲染场景里。** 这很可能是**单帧最大的 GPU 开销** —— 大于 bloom + SSAO + 最终调色 shader 的总和。`level.js:45` 已有注释 "keep the point-light count sane"，但只有一个来源做了预算。

**阴影方面是好的**：全场仅太阳一盏投影灯，PCFSoft 2048²（低画质 1024²）、44m 正交盒、texel 网格对齐防闪烁（`engine.js:135-150, 203-219`）。

### 6.6 🟡 后处理：4–6 个全屏 pass，且低画质也开 bloom

`src/core/postfx.js:168-206`：`RenderPass` → `UnrealBloomPass` → `OutputPass` → 自定义 `FinalShader`，外加可选 `HalfSSAOPass`（`engine.js:315-327`）和 viewmodel overlay `RenderPass`（`engine.js:329-335`）。**没有"关闭后处理"的路径。**

- `UnrealBloomPass` = 5 级 mip × 2 次模糊 ≈ **10 个额外全屏 pass**，且 **`low` 画质档也开着**（`postfx.js:251-262`）。
- `FinalShader`（`postfx.js:58-164`）每像素约 25 次纹理采样：5-tap 冲刺模糊、2-tap 色差、**14-tap 体积光**、辉光、4-tap 锐化掩模、2 次 hash 颗粒。体积光在 `high` 档为 1.0。

已有的正确措施：动态分辨率缩放至 0.72×（`engine.js:251-266`）、帧率上限（`main.js:5547-5548`）、低画质档关闭体积光/色差/SSAO。

### 6.7 ✅ 内存泄漏：无

`src/` 中 **`setInterval` 出现 0 次**；所有定时器是一次性 `setTimeout` 且会自我过期或被清理。**没有任何 per-spawn / per-enemy 的事件监听器**。所有 `CanvasTexture` 在初始化时创建一次，**没有 per-frame 纹理创建**。FX 粒子系统完全池化（`Points` + `InstancedBufferGeometry`，`fx.js:199-246`；火花 `fx.js:425-472`；曳光 `fx.js:552-567`；贴花 `InstancedMesh` `fx.js:633-662`）。布娃娃是纯数学，无网格（`enemy.js:1693-1761`）。

小瑕疵：`fx.js:1329` 的 `get lastMuzzle()` 每次调用 `.clone()` 一个 Vector3；`enemy.js:2104` 每次重建都 dispose 一次共享几何体。

### 6.8 ✅ 实测帧率健康

无头 Chrome + Metal 后端，1280×720：`ai-probe` 多轮实测 **57.6 / 58.7 / 59.4 / 59.6 / 59.8 fps**。CPU 侧没有崩溃性瓶颈。

但注意：**这是集显/无头环境下的数字，不能代表低端设备**。§6.5 的点光源和 §6.6 的 bloom 才是低端设备的真正杀手。

## 7. 工程与流程问题

### 7.1 🟡 测试套件不自包含

`npm test` 唯一失败的 5 项（`tools/minimap-zone-render-test.mjs`）**并非代码缺陷** —— 该测试需要 `:5174` 开发服务器（脚本头部自述"needs the dev server on :5174"），而 `npm test` 不启动它。手动启动后 5/5 全过。

问题在于：**该测试无法区分"服务器没起"与"真实回归"**，失败时只输出 `{}` 和 5 条 FAIL，看起来像代码坏了。应让脚本自行拉起服务器，或至少在启动失败时给出明确的 SKIP 而非 FAIL。

### 7.2 🟡 公平性探针未接入 CI

`tools/` 下有 5 个直接针对公平性的探针，**没有一个接入 `npm test`**：

| 脚本 | 用途 | 是否接入 |
|---|---|---|
| `versus-1v7-probe.mjs` | 1v7 旧行为对照组 | ❌ |
| `versus-solo-fill-probe.mjs` | 单人开局补位公平性 | ❌ |
| `versus-4v4-friendlyfire-probe.mjs` | 4v4 友伤 | ❌ |
| `fairness.mjs` | "称职人类玩家"伤害尖峰探针 | ❌ |
| `ai-probe.mjs` | AI 行为探针 | ❌ |
| `conquest-econ-model.mjs` | 征服经济模型 | ❌ |

**§3.1 的波次死锁，本可被 `ai-probe.mjs` 的既有指标（`engagedWithLosPct`、`avgDistNoLos`、`damageTotal`）自动捕获** —— 这些指标已经存在，只是没人把它们做成断言。

### 7.3 🟡 BR 模式实际不存在

`src/entities/brBot.js`（777 行）**完全没有被使用** —— 没有任何模块 import `createBrBot`。LAN 的 `'br'` 房间模式（`main.js:5676`）跑的是 versus/conquest 路径。文档中描述的"大逃杀"作为独立模式并不存在。

### 7.4 🟡 `__game` 调试接口缺少就绪信号

`window.__game`（`main.js:7222`）在模块加载时即暴露，但 `hud`/`level` 要到 `boot()` 执行到 `main.js:2866` 才存在。自动化脚本在此之前调用 `startGame()` 会得到 `TypeError: Cannot read properties of undefined (reading 'setStreak')` 这种难以定位的报错（本次审查即遇到）。应暴露 `window.__game.ready` 标志。

## 9. 未能验证的部分

诚实标注本报告的边界：

1. **未做 GPU 逐帧 profiling** —— 缺 `renderer.info` 遥测，§6.5 的点光源数量（~34）是静态构造点枚举，实际数量取决于 `shopLights` 的随机数与 MOTH 盟友是否存在，**可能有 30% 误差**；即便如此 25+ 点光源仍然是严重问题。
2. **未在真实多台设备上验证 LAN** —— §2.6 的结论来自代码审阅，攻击可行性的实际复现未做。
3. **TTK 数字为静态推导** —— §2 的换算假设持续 LOS、无掩体 peek 周期、无反应延迟，**真实 TTK 会比表中更长**。
4. **AI 探针的自动瞄准玩家不等于人类玩家** —— §3.1 的结论对"静止或原地开火的玩家"成立；结论"wave 8/12 时玩家不会受到任何伤害"在玩家主动向敌人推进时可能不成立（实测 45 秒内玩家确实零伤害，但 45 秒里玩家没有主动移动）。
5. **剧情矛盾基于文本比对**，未做玩家视角的实际通关走查。
6. **未审查** `src/systems/interact.js`、`src/systems/barks.js`、`src/systems/milestones.js` 的深度逻辑（仅做分配/监听器扫描）。
