# 玩法模式 × 出生系统 × 敌人 AI — 整体改进方案

> 版本：V0.3.5 之后的设计审查与改进路线。
> 问题来源：不同玩法的出生点、剧情推进、敌人 AI 不应该都套通用的脚本和算法壳子；剧情模式要有完整推进线和环节目标；4 种玩法的任务推进/出生地/任务目标要有各自的模式语言；LAN 的合作生存与阵营对抗要有不同的推进模式。

---

## 0. 现状诊断

### 0.1 共享程度（问题核心）

| 机制 | 现状 | 问题 |
| --- | --- | --- |
| 波次脚本 `startWave/updateWaves` | campaign / rotation / survival / defend / extract / LAN co-op **全部共用**（main.js:2724-3100） | 14 关战役和无尽生存用的是同一个 `total = min(14, 3+n+coopBonus)` 公式 |
| 出生算法 `pickSpawnPoint` | 全 PvE 模式共用（main.js:1921-1949） | 唯一变化是 34% 侧后概率；战役关只靠 `spawnRect` 裁矩形 |
| 敌人 FSM `Enemy` | 全模式（含 versus bot）一个类 | AI 不知道自己在打什么模式：守点敌人和猎杀敌人行为一样 |
| AI Director | 单实例全 PvE 共用 | 没有"叙事节奏"概念，只会维持交战压力 |
| 出生点数据 `level.spawnPoints` | 单一全局表（level.js:6339-6406） | 没有 per-mode / per-op 出生表，没有"进攻方向"语义 |

### 0.2 LAN 阻塞级 Bug（先于一切设计工作修复）

1. **房间永远是 coop**：`joinLan` 不传 `mode`（main.js:4535-4544）→ 服务端容量恒为 4，versus 勾了也进不了第 5 人。
2. **敌人伤害全记房主**：`enemyCtx.damagePlayer` 只绑定 `applyPlayerDamage`（main.js:4224），client 实质无敌。
3. **PvP 伤害链断**：client 发不出 `pdmg`（lanClient.js:479-481）；受害端收到也不掉真实 HP（main.js:4636-4639）；host 复核不含玩家 avatar（main.js:4892）。
4. **击杀归属错队**：host 复核 client 击杀时用 `net.team`（房主恒 team 0）（main.js:3493-3496）。
5. **versus 无终局**：`checkVersusWin` 只 toast 不结算（main.js:1512-1520）。
6. **client 手雷是哑弹**：扣雷出手但 `updateGrenades` 对 client 跳过（main.js:5305）。
7. **里程碑只认房主位置**：reach/hold/collect 判定只用 `controller.pos`（main.js:1232-1234）。
8. **versus 掩体预约泄漏**：bot 走 co-op director 的 coverReserve，而该实例在 versus 不 tick，死人预约永不释放（main.js:4241-4247 × director.js:66-72）。

### 0.3 AI 设计弱点（与设计目标冲突处）

- **软透视**：新刷敌人白拿玩家位置 ±3-10m（director.js:185-197），失明后每 3.4-7s 滴灌一次（director.js:202-220）——潜行/隐蔽打法价值为零。
- **无巡逻**：未警觉敌人站桩摇头（enemy.js:1049-1050），战场在玩家开枪前是死的。
- **flank 不是包抄**：只是横向平移权重（enemy.js:1207-1211），director 分侧只看 x 符号（director.js:401-405），没有绕后路径规划。
- **命中纯掷骰**（enemy.js:1750-1756），玩家身法无法规避已骰中的子弹。
- **难度=数值**，maxFiring 全 tier 恒 2，rusher/sniper 绕开开火预算——D1→D5 的压力差异大半来自命中率。
- **卡死瞬移**会在 12-26m 环带无预警贴脸刷敌（main.js:5453-5455）。
- `brBot.js` 777 行死代码，无 import。

## 1. 设计原则（行业最佳实践映射）

| 原则 | 出处 | 落到本项目 |
| --- | --- | --- |
| **模式语言**：每个模式用一句话能说清的"幻想"，出生/目标/AI 都为这句话服务 | CoD 模式设计 | 见 §2 模式定位矩阵 |
| **节奏曲线**：紧张→释放→喘息，不是恒压 | L4D AI Director | Director 增加 `pacing` 状态机（build/peak/release），战役按剧情节拍驱动，生存按波次正弦驱动 |
| **遭遇战设计**：出生点携带"进攻方向+掩体链路"语义，不是坐标集合 | Halo 遭遇战、Destiny spawn zone | 出生点升级为 SpawnZone（见 §3） |
| **可读性**：玩家能学会"这个模式的敌人从哪来、要什么" | CS 定点刷新、Tarkov scav 区 | 每个模式 2-3 条可学习的进攻轴线 |
| **信息公平**：AI 情报必须有来源（目击/枪声/友军报点），禁止免费全图透视 | 潜行类游戏通则 | 砍掉 director 白送情报，改"情报来源制"（见 §4.3） |

## 2. 模式定位矩阵（每个模式的"一句话幻想"）

| 模式 | 一句话幻想 | 推进模型 | 出生逻辑 | AI 行为画像 |
| --- | --- | --- | --- | --- |
| **战役 OP** | "你是灰狼，在卡里姆的棋盘上一步步拆掉他的局" | 剧本化节拍链（见 §4） | **每关独立 SpawnZone 表**，按剧情阶段解锁扇区 | 守军画像：巡逻、阵地、被惊动后求援 |
| **无尽生存** | "顶住，一波比一波狠" | 波次 × 难度正弦（每 3 波一个峰值） | **以玩家为圆心的收缩环带**：随玩家移动重锚，交战带半径随波次收窄（45→28m） | 猎手画像：主动索敌、包围、不给喘息 |
| **区域防守** | "这个点不能丢" | 守住累计时长，敌方分波次进攻 | **进攻矢量制**：敌人从指向目标区的 2-3 条轴线远端成建制刷出，沿掩体链路推进 | 进攻方画像：以目标区为终点，掩护交替推进 |
| **清场撤离** | "杀出一条路到撤离点" | 清场 → 撤离窗口 → 拦截 | **封锁线制**：敌人在玩家与撤离区之间的走廊布防 + 撤离倒计时触发追击波 | 拦截者画像：先守撤离走廊，后追猎 |
| **标准轮换** | "四块战区轮着打，什么都会来" | 战区轮换 × 模式轮换（保留现有规则） | 继承当前站点的模式规则 | 继承当前模式画像 |
| **LAN 合作** | "一支小队打一场升级的战争" | **行动章节制**（见 §5.1） | 小队集结点 + 章节目标驱动 | 章节画像随目标切换 |
| **LAN 对抗** | "4v4 占领与歼灭" | **回合制 + 区域控制**（见 §5.2） | 阵营基地 + 前线重生（按地图控制度前移/后撤） | 班组画像：抱团、集火、保枪线 |

关键改变：**出生逻辑不再是"一个算法 + 参数"，而是每种模式一套生成器**，共享的只有 nav 可达性校验和节流器这两个底层件。

## 3. 出生系统重构：SpawnZone 取代裸坐标表

### 3.1 数据结构

把 `level.spawnPoints` 升级为带语义的 SpawnZone：

```
SpawnZone {
  id, region: 'street'|'souk'|'rail'|'port'|'north'|...,
  points: [...],                  // 坐标（复用现有表）
  attackVector: {x,z},            // 进攻方向（朝哪个目标打）
  coverChain: [...],              // 推进链路上的掩体点（喂给 cover.js）
  unlockWhen: (G)=>bool,          // 解锁条件（波次/剧情阶段/区域控制）
  modes: [...],                   // 哪些模式可用
  weight: 1.0
}
```

### 3.2 各模式生成器

- **战役**：每关 OP 定义自己的 `spawnPlan`——按剧情节拍列出 `zoneId + 触发条件 + 兵种配比`。OP06 检查站的敌人就该从北方公路和两侧巷道成建制压向闸门，而不是在 18-45m 环带里随机摸点。
- **生存**：以玩家当前位置为锚，选 `unlockWhen` 满足的 zone 中**距玩家 2 条轴线以上**的 2-3 个 zone 交替刷，每波换一批（防背点）；34% 侧后规则保留但改为"选玩家朝向盲区里的 zone"。
- **防守**：选定 objective zone 后，计算 2-3 条通往它的进攻轴线，敌人只在轴线远端 zone 刷出，沿 `coverChain` 推进——玩家读得懂"敌人从东边来"，能架枪能埋雷。
- **撤离**：分两阶段——清场阶段敌人在撤离区周边 zone 布防（standoff 姿态）；撤离倒计时启动后，在玩家**身后**刷追击波（rusher 占比提高），制造"边打边退"。
- **轮换**：用站点的模式规则。轮换本身已经提供了变化，不动。

### 3.3 玩家出生

- **战役**：保留每关固定 `start`（叙事需要），但补**重生检查点**（见 §4.4）。
- **生存/防守/撤离**：不要全随机。按"战区锚点轮换 + 区内 jitter"——即现有 site 轮换保留，但出生在站点内的 3-4 个候选点中按"离上一局死亡点最远"选取。全随机会让玩家无法建立地图认知，固定又会被背板；轮换+区内随机是 CoD 的标准答案。
- **LAN 合作**：小队出生在同一 zone（集结感），随后章节目标把队伍拉开。
- **LAN 对抗**：基地固定出生 + 前线重生点（前线点随区域控制度在 2 个候选位之间切换）。

## 4. 战役模式：从"波次模板"到"剧本化任务"

### 4.1 任务内结构：Beat 链

每关从 `mode + waves` 升级为 **beat 链**（仍声明式，数据驱动）：

```
op.beats = [
  { type:'infil',   text:'潜入市场，不要惊动守军',  spawnPlan:'stealth',  ai:'garrison' },
  { type:'assault', text:'拿下棚屋', trigger:'zoneEnter', spawnPlan:'marketAxis', ai:'counterattack' },
  { type:'defend',  text:'顶住反扑 45 秒', hold:45, spawnPlan:'marketAxis+rear', ai:'assault' },
  { type:'extract', text:'到公寓正门撤离', zone:..., spawnPlan:'interceptors', ai:'pursuit' },
]
```

渲染层复用现有 objective UI；执行层是一个 `beatRunner`（推进条件：清场/计时/进区/击杀数/交互）。现有的 `op.radio.at` 钩子、`bossIntro`、`outro` 全部保留，挂在 beat 上而不是挂在 wave 上。

### 4.2 14 关升级样板（先改 4 关做验证）

| 关 | 现状 | 升级后 |
| --- | --- | --- |
| OP02 市场 | defend 45s 一波流 | 潜入（可选不惊动）→ 抢棚屋 → 守 45s（双入口进攻轴线）→ 撤离截击 |
| OP05 南院 | survival 4 波 + Boss | 搜车（交互）→ 暴露警报 → 哈桑带卫队进场（Boss 有 2 个 shield 扈从）→ 收尾 |
| OP09 北楼 | survival 2 波室内 | 破门 → 逐房清理（CQB spawnPlan）→ 卡里姆办公室对峙（Boss 阶段战：血量阈值触发他换位/叫援军） |
| OP14 最后一吊 | survival 4 波 + Boss | 港区推进（集装箱阵轴线）→ 水边侧袭 → 萨利姆 + 吊臂观察哨联动 → 撤离 |

### 4.3 AI 情报公平化（全模式收益，战役感受最明显）

- 删除 director 的"开场白送 investigate"（director.js:185-197）和"失明滴灌"（202-220）。
- 改为**情报来源制**：敌人知道玩家位置只能来自 ①自己看见 ②听到枪声（42m 已有）③同伴报点（contact 后 22m 广播，已有 comradeLost 通道可复用）④战役脚本指定的"守军预警"。
- 未警觉敌人加**巡逻**：给每个 SpawnZone 配 2-4 个巡逻路点（数据可先从 attackVector 沿线自动生成），`idle` 拆成 `patrol`/`post`（哨兵站桩）两态。这让 OP02 的潜入节拍成立，也让整张地图在玩家开枪前是活的。

### 4.4 检查点

战役关按 beat 存档（localStorage 增量，每 beat 完成写一次），阵亡从当前 beat 重来而不是整关重打。这是单人体验的底线配置（14 关 × 10 分钟整关重打 = 弃坑点）。

### 4.5 Boss 战阶段化

Boss 从"血厚的大兵"升级为 2-3 阶段：
- 哈桑（OP05）：卫队存在时减伤 50%（逼先清场）；血量 50% 触发冲锋模式（rusher 化）。
- 卡里姆（OP09）：70%/40% 血量各换位一次（办公室→夹层→作战室），换位时叫一波援军。
- 萨利姆（OP14）：阶段三启动吊臂火力支援（artillery 已有，改敌用）。
实现成本低：Boss 已支持 `bossHp/bossScale/bossSpawn`，阶段只是"血量阈值触发脚本动作"。

## 5. LAN 双模式：两套推进模型

### 5.1 合作生存 → 合作行动（Co-op Operation）

现状问题：无终局、升级只归房主、里程碑只认房主、client 无敌（bug）。

推进模型改为**章节制**（复用战役 beat 引擎，co-op 特化）：

1. 一局 = 3 章 × 2-3 波，章节目标从 {守点/搜集/护送信标/清除} 中抽取，打完第三章出撤离窗，全员进区 = 胜利结算（进排行榜的"合作榜"）。
2. **里程碑改为全队贡献**：reach/hold 判定改为"任一存活队员在区内"，collect 交互点挂在所有端（修 G 节 bug 的同时完成）。
3. **升级卡全员各选各的**：host 广播 `upgradeOffer`，各端本地选，回报 host 合并进各自 `upgrades`。
4. **倒地/救援**替代 4s 原地复活：被打倒进入流血倒计时，队友按 E 拉起；全灭才算失败。这是合作模式的情感核心，也是"章节制"的失败条件。
5. 缩放公式保留 `coopBonus`，但章节目标难度也按人数缩放（hold 时长 ×(1+0.25×(n-1)) 等）。

### 5.2 阵营对抗 → 回合制征服（Conquest-lite）

现状问题：无终局、出生固定 8 锚点、毒圈是唯一的节奏器但伤害粗糙（10%maxHP/s）、PvP 链路断（先修 bug）。

推进模型改为：

1. **回合制**：BO3 回合，每回合 90 秒 + 先到 25 杀；回合计分板 + 换边，终结"无限 TDM"。
2. **区域控制**（替代毒圈当节奏器）：地图 3 个控制点（街区/集市/北站三选一复用 OBJECTIVE_SPOTS），占领提供重生前移点和每秒团队分。毒圈降级为**加时赛机制**（回合平分时启动快圈）。
3. **出生保护**：重生后 2s 无敌 + 不出现在敌人 15m 视线锥内（重生选点评分加入"敌视线惩罚"）。
4. **bot 行为班组化**：bot 不再 `nearestHostileActor` 各自为战，teamBrain 增加"2-3 人一组抱团推进控制点"的组目标；落单 bot 优先向最近队友收拢。
5. bot 数值去外挂化：D4 + damageMult 1.8 的填位 bot 比真人准，改成 D3 基准 + 命中率随回合比分落后方小幅补偿（橡皮筋在 bot 侧，不在真人侧）。

### 5.3 LAN 必须先修的 Bug 清单（§0.2 全部）

修复顺序即优先级：房间 mode 传递 → 敌人伤害路由（按 enemy.targetId 路由到对应端）→ PvP 伤害闭环（pdmg 允许 client→host→受害者，受害者本地结算 HP 并回报）→ 击杀归属（用射手 id 查队）→ versus 结算流程 → client 手雷（host 模拟广播）→ 里程碑全队判定 → versus 掩体预约（改用本队 director 实例）。

## 6. 敌人 AI：一套底层，四套画像

底层（perception/navgrid/cover/steering）保持共享——这部分质量是好的。**分化发生在画像层**：每个敌人带一个 `aiProfile`，决定状态优先级和目标选择：

| 画像 | 用于 | 关键行为差异 |
| --- | --- | --- |
| `garrison` 守军 | 战役未警觉段 | patrol/post 循环；视野缩窄 15%；被惊动先奔向警报点而非直接扑玩家；求援呼叫（拉邻近 zone 敌人） |
| `hunter` 猎手 | 生存 | 主动用威胁场反推玩家位置（被压制的火线反包围）；包围时自动拉开 120° 夹角；无喘息窗口压缩 |
| `assault` 进攻方 | 防守/战役反扑 | 目标是**区域**不是玩家：沿 coverChain 向目标区推进，玩家只是路障；进区后占点压制 |
| `interceptor` 拦截者 | 撤离 | 布防期高 standoff 打阵地；追击期 rusher 化、开火预算放宽 |
| `squad` 班组 | 对抗 bot | 组目标优先于个人目标；保枪线（不越过队友火线）；残血后撤向队友收拢 |

落地方式：`Enemy.chooseState`（enemy.js:1012-1043）现在是一个长 if 链，把"目标选择"和"状态转移"各抽成一个 profile 可覆写的策略函数，默认实现 = 现状。这样不动底层就能逐模式换行为，风险可控。

配套修正（不分模式都该做）：
- 真包抄：flank 角色的移动目标改为"玩家位置 ±90-150° 扇区里、距玩家 14-20m 的 nav 可达点"，用 A* 走过去而不是直线平移。
- 压制改移动：suppression>0.55 的推进中敌人就地寻找最近掩体（不只降命中）。
- 卡死瞬移加预警：瞬移目标点若距玩家 <26m，改为找 26-40m 环带点 + 触发一声敌方向 bark（玩家能听见"侧翼有人"）。
- 开火预算覆盖 rusher/sniper：maxFiring 按 tier 差异化（D1=1 … D5=3），rusher/sniper 纳入计数。
- 命中模型保底公平：骰中后若玩家在过去 0.15s 内有 >3m/s 的垂直于弹线的位移且已进掩体，追加一次几何复核（复核不过则 miss）——保留手感，消除"进了掩体还被打"的挫败感。
- `brBot.js` 删除（或确认无引用后归档），避免后人误读。

## 7. 实施路线（按依赖排序，每期独立可发布）

**Phase 0 — LAN 止血（1 期）**：§0.2 全部 bug。这是"对抗/合作两种推进模式"能成立的前提，无设计争议。

> **状态：已完成（含实机验证）。** 实际修复 10 项：8 项原清单 + 实机验证新发现 2 项——①client 阵亡会把房主一起打死（无 target 的 `down` 事件穿透到房主自身）；②AI 击杀房主/宿主不计入对方团队分。环境击杀（毒圈/空袭）不再误记房主队伍。回归守卫见 `tools/versus-guard-test.mjs` 的 "Phase 0 LAN fix guards" 一节；协议级联调探针 `tools/lan-coop-probe.mjs`（需一个真实房主页面，不入 CI）。已知环境约束：房主标签页被浏览器切到后台会冻结全局模拟（rAF 节流），房主机请保持前台。
**Phase 1 — 出生系统**：SpawnZone 数据结构 + 生存/防守/撤离三个生成器 + 站点内玩家出生随机化。纯后端改动，AI 不变也能立刻感到"模式不一样了"。

> **状态：已完成（逻辑层 + 真实数据校验）。** 落地为纯逻辑模块 `src/systems/spawn.js`（zone 按 level 命名区域分桶、`zonesWithinRect` 裁剪当前战区、survival 双轴轮换 / defend 进攻轴线 / extract 布防-追击两段式、`pickPlayerSpawn` 远离上次死亡点）。main.js 接入点：`startWave` 先走模式生成器、失败回落旧池选点；`spawnReinforcements` 沿轴线续兵；extract 清场即触发身后追击波（rusher 倾向 + VEGA 播报）；单人自由玩法玩家出生在战区内离上一次死亡最远的点。回归测试 `tools/spawn-test.mjs`（19 项，已入 npm test）。
>
> **状态：已强化（分层落地 + 点级几何 + 可复现审计 + 真实地图校验）。** Phase 1 的初版仍留了三个隐患，本轮一并解决：
>
> **① 三层分离（子strate / 语义 / 随机）。** 距离规则统一到 `SPAWN_RULES`（`systems/spawn.js` 单一来源，main.js 引用而非重定义——此前 spawn.js 的 18/55 是"zone 质心带"、main.js 的 20/46 是"点位带"，同名不同量）。**语义层（模式决定从哪边来）各模式独立，**随机层只在选定的边内选具体点位。旧的 34% 侧后掷骰被彻底移除：它是"随机决定方位"，会让同一模式在不同波次换边——现在整波一次决定侧向，34% 改为**波级**开关而非每敌一次。
>
> **② 几何判定改为点级。** 初版按 zone **质心**做距离门禁，在真实地图上是错的：`container_yard` 横跨 120m（(54,-93)→(108,24)），质心 (70,-67) 不代表任何实际出生点，把玩家逼到港区北端时整区被误杀。现在所有生成器先收集 zone 内的**候选点**（满足距离带的点，带自身方位角），语义层基于候选点判定；zone 只保留"轮换单位"的角色。撤离的两段式也改用**线段投影**（走廊=点到玩家→撤离点连线的垂距）而非原始方位角差。
>
> **③ 可复现 + 审计。** 每波从 `(session seed, mode, wave)` 派生独立 rng，`?seed=<n>` 可复现整局波次；`G.spawnAudit` 记录每波计划（模式/来源/种子/玩家位置朝向/被烧毁的 zone/每个落点的距离与扇区），`window.__game.spawnPlan(mode, wave)` 用记录中的输入**重放**该波。实测：同 seed 两次独立运行，波次计划逐点一致。
>
> **④ 真实地图校验（`tools/spawn-audit-probe.mjs`，已入 npm test）。** 用真实 level + 真实 `OBJECTIVE_SPOTS` 跑四个战区 × 五个站位，校验距离带、后方面额上限、可行走性、defend 进攻轴、extract 走廊布防、种子多样性。探针查出并已修的真实问题：① 撤离走廊无人把守（港区三个撤离点全空）——改用线段投影后修复；② 玩家背后 50-60m 无带内点位（集市南端整段无出生点）——补 6 个点位；③ 街道站点所有点位集中在 x∈[-7,7] 主街，从站点锚点看非前即后、**没有侧翼**，后方面额必然破上限——在两条横街补 4 个侧翼点（-26.1,34.3 / 29.1,31.1 / 28.3,23.9 / -30.9,31.1）。
>
> **⑤ LAN 合作落点分散。** 原先所有客户端都落在 `site + (2.2, 1.0)` 同一点，四人叠在一起（手雷友伤、医疗包互踩）。现在 `assignCoopRallySpot` 由**全体玩家名单**派生环位，主机与客户端各自用同一份名单推导同一个环（名单随 start 事件广播），环半径随人数增长以保证最小间距 ≥2.6m。回归：`tools/coop-rally-test.mjs`（9 项）。
**Phase 2 — AI 画像**：profile 策略层 + garrison/hunter/assault/interceptor 四画像 + 情报公平化 + 真包抄 + 巡逻。

> **状态：已完成（逻辑层 + 单元/守护测试；实机手感待验）。** 落地为纯逻辑模块 `src/systems/ai/profiles.js`：六套画像（default/hunter/assault/interceptor/interceptorPursuit/garrison/squad）+ 三个纯函数（`pickFlankPoint` 侧后扇区路点、`pickPatrolPoint` 单向转向巡逻腿、`decideIntel` 公平情报决策）。main.js 按模式盖画像：生存=hunter、防守波=assault、撤离布防=interceptor、追击波=interceptorPursuit、对抗 bot=squad、战役首波=garrison（巡逻+只认刺激源，摸近背刺成立）；zoneAnchor 画像无新鲜情报时向任务区域推进（"目标是区域不是玩家"）。director.js 情报公平化：删掉两段免费透视（开局/滞后直接给玩家坐标±3-10m），改为"刺激源（枪声/弹着/队友阵亡）±2-7m > 区域质心±12-20m > 无"，versus bot 全跳过（brain 独占情报）；flank 指派时算侧后 80-150°/14-20m 扇区点并过 nav 校验。enemy.js：新增 patrol 态（驻军绕岗+扫头）、flank 路线承诺制（中途见敌不脱线，路线上可还击）、压制 >0.55 改移动（减速 45%+避火线+要掩体，rusher 豁免）、rusher/sniper 纳入全局开火预算（maxFiring D1=1…D5=3）、晚闪避复核（命中且 0.15s 内高速位移 → 一次几何复核）。perception.js：4.2m 近身自动发现尊重朝向——安静+背后+未警觉不再 360° 发现（背刺成立）。main.js：卡死瞬移改 26-40m 远环 + 侧翼 bark 预警。回归：`tools/ai-profile-test.mjs`（22 项，入 npm test）+ versus-guard "Phase 2 AI-profile guards"（20 项）。garrison 巡逻的战役级展开（未警觉段编排）留给 Phase 3 beat 引擎。
**Phase 3 — 战役升级**：beat 引擎 + OP02/05/09/14 四关样板 + 检查点 + Boss 阶段化。之后按同样模板翻新其余 10 关。

> **状态：已完成（引擎 + 四关样板 + 检查点 + Boss 阶段化；实机验证待玩家试打）。** 落地为纯逻辑模块 `src/systems/beats.js`（beatForWave/beatMode/beatObjective/beatComplete/operationWaves），**一节拍 = 一波**，完全复用现有波次循环（升级选卡、电台、objective UI、结算全部保留）。新增两种节拍类型：`infil` 潜入（进区即完成、击杀可选、驻军画像 AI 沿用 Phase 2 的 garrison 巡逻+只认刺激源）、`interact` 交互（搜车按 E，spot 支持 'site'=当前轮换站点中心）。main.js 接入：modeForWave/startWave/setupObjective/onObjectiveDone/updateWaves 全部按节拍分流（目标驱动节拍只从 onObjectiveDone 推进、清场驱动节拍走原升级流、boss 节拍看 bossBeatSpawned 不被扈从卡死）；`advanceBeat` 收口升级选卡或 finishOperation。**检查点**：story.js 新增 dod.campaign.beat.v1 存储，每节拍开始写、通关清、startGame 自动从检查点恢复（跳过已看过的开场动画），节拍制战役阵亡不再提交榜单、按钮变"从节拍 N 重试"。**Boss 阶段化**：op.bossPhases 按 HP 阈值触发一次——warden（扈从存活时 damageResist 0.5）、charge（advanceSpeedMult 冲锋）、relocate（换位+叫援军）、escort、artillery（玩家连杀系统敌方化，萨利姆吊臂标射）。四关样板：OP02 潜入→夺取→守 45s→撤离截击；OP05 搜车→警报→哈桑(卫队减伤+半血冲锋)→收尾；OP09 破门→逐房→卡里姆(70%/40% 两次换位叫援军)；OP14 推进→水边侧袭→萨利姆(60% 吊臂炮火/30% 亲卫)→登船。回归：`tools/beats-test.mjs`（39 项，入 npm test）+ versus-guard "Phase 3 guards"（24 项）。其余 10 关翻新 = 往 story.js 抄 `beats:` 数据即可，无需再动引擎。
**Phase 4 — LAN 模式深化**：合作章节制（倒地救援、全队升级）+ 对抗回合制征服（控制点、重生保护、bot 班组化）。

## 8. 验收标准（每 Phase 的可观察指标）

- P1：生存模式连续 5 波，敌人来源 zone 不重复率 >60%；防守模式玩家能用"敌人从哪条轴线来"做预判（可测：轴线内击杀占比 >70%）。
- P2：玩家不开火接近巡逻敌人 4m 内可完成背刺（现状：4.2m 即 360° 发现，必被反打）；蹲坑 >8s 不再触发"敌人直线摸过来"。
- P3：OP02 完整体验到潜入→夺取→防守→撤离四段；阵亡从当前 beat 重开。
- P4：合作局有胜利结算画面；对抗局有回合记分板与换边；8 人房真实可进。
